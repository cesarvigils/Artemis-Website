## 0. Headline

The site is genuinely well adapted at 100% text size: **zero horizontal overflow on any page at any of the ten viewports** (proven with `body { overflow-x: clip }` lifted, so nothing is merely being hidden), the anchor `/#results` clears the fixed header at every width, the garage carousel snaps and steps correctly on touch and pointer alike, and the mobile menu is correct from 320 up.

Three things break it:

1. **At 200% text scaling the site loses its navigation entirely.** The compact header CTA cannot shrink, so it crushes the hamburger to 13–16 px and pushes it off the device viewport. Playwright could not click it on any of the five pages. The wordmark is clipped mid-letter in the same bar.
2. **Tap targets.** Every footer/channel/404 link is 22.1 px tall — under the 44 px touch bar on phones and under the WCAG 2.5.8 AA 24 px bar even on desktop. The hamburger itself drops below 44 px wide at 320.
3. **Responsive images are mis-described.** The `sizes` attributes on the garage and the About collage describe widths the elements never have; measured against the real bytes on disk, a 275 px garage slide downloads a 1024 w / 69.7 KB file (3.73×), and a 126 px About thumbnail downloads a 640 w / 15.6 KB file (5.08×).

On the harden side there is one build-stopping defect: **emptying `results.json` passes `check:data` and then crashes `astro build`** in `partners.astro`.

## 4. Do not change

1. **`body { overflow-x: clip }` plus the per-section `overflow: clip`.** Lifting the clip and re-measuring every element against the layout viewport found **one** overflowing box on the whole site — the hero image's own `scale(1.3)` mobile crop, which those rules exist to contain (`summary2.json` `A_true_overflow_clip_removed`). The containment is doing real work and nothing is hiding behind it at 100 % text size.
2. **The garage carousel.** `scroll-snap-type: x mandatory` with `scroll-snap-align: start`, native scroll, `overscroll-behavior-x: contain`, 44 × 44 arrow buttons, and a `scroll-padding-inline` that lines slide one up with the container gutter. Measured at all 14 modes: drag moves, the arrows step exactly one slide (242 / 269 / 289 / 306 / 546 / 221 / 270 / 300 / 306 px at 320 → 2560), and the progress thumb is sized to `clientWidth / scrollWidth` rather than sitting at a 1 px stub. This is the best-adapted component on the site.
3. **`scroll-padding-top: calc(var(--nav-h) + 1rem)` and the per-click anchor handler in `initAnchors()`.** The fixed header covers the `/#results` heading at **zero** of the 14 viewport modes; clearance is 80–128 px at 100 % text and 323 px at 200 % (`analyze.mjs anchor`). The decision in `global.css:140-146` not to use a global `scroll-behavior: smooth` is also right and should stay.
4. **The mobile menu's layout, focus trap and `inert` handling.** Panel fits the viewport with zero off-screen links at 320, 360, 390, 414 and 768 on all five pages; `aria-expanded` flips, the label becomes "Close menu", focus moves into the panel, Tab cycles inside it, and `#main`/`.site-footer` go `inert` + `aria-hidden`. Fix the scroll chaining (E5) without touching any of this.
5. **The 17 `@media (hover: hover) and (pointer: fine)` guards.** Every hover affordance — nav underline, garage zoom, driver-number fill, link arrows, partner marks — is behind an input-capability query rather than a width query, and the `prefers-reduced-motion` block clamps `transition-property` site-wide instead of nuking durations. That is the correct way to do it and it held up under touch emulation at every width.

## 5. Caveats on this review

- Everything above is Chrome headless with device emulation. `adapt.md` is explicit that emulation misses real touch, real CPU and browser chrome; the 320×568 hero overflow (E10) and the tap-target findings in particular deserve one pass on a real phone before the fixes are tuned.
- The 200 %-text findings were produced with `document.documentElement.style.fontSize = '200%'`, as specified. That models a browser/OS text-size setting, not pinch-zoom (which reflows differently). The failure mode — an unshrinkable nowrap button in a flex row — is the same either way.
- `img` verdicts compare the **bytes actually downloaded** (from `dist/_astro`, matched against the network log so unloaded lazy images are excluded) against `renderedCssWidth × devicePixelRatio`. Rows where the element is scaled by a CSS transform (the mobile hero) are called out explicitly in E18 rather than silently counted.
- The one console error the harness saw is the test server correctly returning HTTP 404 for `/this-page-does-not-exist`. Not a site defect.
